# Sites execution adapter

Use only when the project/task includes a Site/prototype. Read the current installed official Sites skill and task-relevant references before acting. This adapter defines project boundaries, not helper/tool schemas.

The primary Work conversation owns checkout/registration/source synchronization/manifest/native calls/publication. Delegate research/assets, bounded disjoint source work and review. Do not let workers independently create a second Site, alter hosting identity or publish. For an existing Site, identify and preserve its real project ID/audience. For a new project, do not copy another Site's hosting identity or runtime bindings.

Match requested scope: local-only preview, save-only or deployment. Site creation/publication happens only as part of an actual authorized prototype/build task; creating this process kit is not that task. Use the skill's supported source, packaging and deployment workflow; preserve version/commit evidence.

Use synthetic fixtures and explicitly label simulation. Visual prototype acceptance should cover representative states, viewport/zoom, responsive and keyboard behavior when required. Record whether data/actions are mocked. Do not let a preview imply production backend/access policy.

Follow actual preview/browser capabilities and the skill's selected preview guidance. An unavailable preview/check is NOT_RUN/BLOCKED; do not fabricate captures or install an unsupported alternate browser path.

Use the [UI contract](../templates/UI_DESIGN_CONTRACT.template.md) as the single UI handoff body, with the [handoff envelope](../templates/DESIGN_HANDOFF.template.md) only for transport/identity. Include selected source/reference version, state/component contracts, assets and AC. Treat web implementation as a design/behavior reference for O11, not importable OML. The receiving operator does independent O11 discovery and verification.

For new/material O11 UI, follow the [native-first standard](../docs/standards/O11_UI_NATIVE_FIRST.md): the installed Sites skill is required. Provide review states plus a separate O11 widget/pattern/public-action map, token/class map and evidenced custom exceptions. Label web simulations versus actual O11 components; a Site cannot verify native O11 behavior. Record user acceptance of the exact contract/version before dependent O11 writes; reuse same-scope acceptance. Small maintenance may reuse current design/foundation. This setup authorizes no handbook/prototype operation.

The [canonical mapping contract](../templates/UI_DESIGN_CONTRACT.template.md) owns all component rows and linked token/exception decisions. Provide App view plus Review view covering each UI region, with stable UI-ID navigation/highlight between views. Review view uses/references this single source; generated projections pin source revision/hash and are checked for missing/extra IDs and field drift. Apply the five classifications from the contract to proposed O11 implementation; label Sites web simulation separately. Critical Unverified blocks dependent O11 writes. Use [reference index](../docs/references/cheatsheets/README.md) only for candidates; primary local verifies installed contracts read-only.

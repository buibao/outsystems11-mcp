# O11 execution adapter

In this workspace also read [engineering](../docs/engineering-standards.md), [verification](../docs/verification.md), [recovery](../docs/recovery.md) and [O11 execution protocol](../docs/standards/O11_EXECUTION_PROTOCOL.md). Preserve existing spec/report formats for existing O11 tasks; workflow task packages can link them. Workflow G0 is intake; O11 G0 is target/baseline. Both applicable conditions must be satisfied. Setup-only does not enter the mutation/merge gates.

Use the project-installed official `servicestudio-mcp-oml` skill, pinned deliberately, and only task-relevant references/examples. Do not modify upstream or substitute ODC APIs/source-code build commands for OML mutation. Existing approved project engineering/verification/recovery rules remain relevant; reconcile them explicitly if adopting this adapter.

## Operator ownership

The primary local session is the sole O11 operator/module and owns ALL MCP calls. Reads can create/follow pending snapshots; workers should use labeled sanitized snapshots instead of independently managing live sessions. Builder authors proposed Model API code; primary inspects schema/examples and applies it. Keep approved token in operator memory and reuse across ordinary reconnects in the same session. Do not expose it to worker assignments, files, logs or handoffs.

Before writes identify live module/style plus environment, current model/pending state and writers; verify review setting with available evidence or user confirmation. Establish a recoverable O11 checkpoint appropriate to the change. Do not repeat checks still supported by unchanged relevant evidence. Different project profiles/branches do not provide writer isolation.

## Translation and implementation

Map accepted design to real project/native components, theme tokens, Screen/Block boundaries, input/event/structure contracts and local/server behavior. Preserve native semantics and justify scoped styling. Confirm dependency availability/version; do not invent prefixes or application architecture. A UI prototype's fake roles/transitions do not become production policy.

Inspect affected model before a bounded mutation. Assert relevant preconditions, read back actual results and compare complete affected validation identities to baseline. Check flow readability and affected consumers. A proposed lambda, saved copy, accepted model and runtime are distinct states. Preserve unchanged user work.

## Integration and runtime

Follow MODEL_REVIEW / MERGED / RUNTIME_VERIFIED honestly. MODEL_REVIEW stops before merge. MERGED includes actual manual Compare and Merge acceptance and a fresh accepted-live readback. RUNTIME_VERIFIED additionally requires identified publish/environment plus required runtime checks. Agent permission to invoke merge does not remove developer review. Never change review mode automatically.

Publish, reference refresh/addition, reset/discard, migrations, external configuration or deployment need authority for that operation. Reuse valid authority already given; do not ask again solely because a gate was reached. Inspect actual disabled tools; do not enable them. If the user publishes manually, identify actual version/environment before runtime testing.

One runtime QA worker may interact with an authorized browser context/fixture; isolate concurrent suites. Protected actions need server-side allowed/denied checks when affected. UI-only work still checks relevant page access and unchanged boundaries; do not use blanket N/A just because no CRUD was added.

## Failure and portability

After timeout/interruption, inspect state before retrying; do not replay merge/mutation blindly. Session lifecycle follows actual tool schemas and revision-specific observed behavior. Keep local compatibility notes separate from upstream. Temporary snapshots are not backups; model restore does not undo data/external effects.

When moving between infrastructures, verify supported transfer/provenance/IPP and compatibility as part of that task. Prefer development in the intended approved infrastructure. Work's hosted environment cannot be assumed to reach the Service Studio loopback endpoint on the user's Windows machine; use a versioned artifact handoff unless a separately approved bridge is actually available.

UI work follows the [native-first standard](../docs/standards/O11_UI_NATIVE_FIRST.md) and [lean workflow](../docs/standards/LEAN_UI_WORKFLOW.md). Before design inspect actual Screen/UI Flow theme/base chain and layout, resident widget/pattern signatures and public actions, classes/tokens. Before dependent UI writes require accepted contract revision and resolved mapping. Button/CSS imitations do not establish pattern reuse; missing dependencies require an explicit gap/decision, not cloning or automatic refresh. Primary plans and implements; builder delegation is optional. Representative runtime evidence before broad expansion follows existing Workflow G2 and authorized O11 G4/G5, without overriding CompletionTarget.
